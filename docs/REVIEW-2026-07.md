# SwiftWUI — архитектурное ревью (2026-07-02)

Метод: multi-agent ревью (10 параллельных ревьюеров по модулям + сквозным
измерениям), дедупликация, **адверсариальная верификация** каждого бага
(critical/high проверяли 2 независимых скептика с задачей опровергнуть),
затем панель из 3 архитекторов (fix / redesign / ecosystem benchmark).

Итог верификации: **56 дефектов подтверждено трассировкой кода
end-to-end, 0 опровергнуто**. Ниже — только реальные, достижимые из
пользовательского кода проблемы.

---

## Вердикт

Каркас фреймворка спроектирован грамотно и его **не нужно переписывать
целиком**. Но у него отсутствует одна несущая абстракция — **идентичность
компонента в дереве** — и из-за этого центральное обещание SwiftUI-подобного
API (`@State` живёт между ре-рендерами) **сломано для любого вложенного
компонента**. Плюс три класса дефектов кластеризуются на трёх «швах»:
идентичность/жизненный цикл, применение патчей в DOM, экранирование на выходе.

Все три архитектора сошлись на одном: **внутренний частичный редизайн
рантайма** (persistent instance-tree), сохраняющий публичный API и хорошие
внешние слои (TagBuilder, Reconciler, Styles, Showcase). Полный редизайн
выбросил бы то, что реально хорошо; точечные патчи по одному воспроизвели бы
хак идентичности пятнадцать раз.

### 57 дефектов сводятся к ~10 корневым причинам на 3 швах

1. **Нет структурной идентичности при разрешении body** → @State сбрасывается,
   `.task`/`.onChange` коллизии по call-site, переиспользование `EventListenerID`,
   утечка реестра, сброс состояния в NavigationStack, морфинг веток
   ConditionalTag. **8+ находок, ОДНА причина.**
2. **Применение патчей в DOMRenderer не тестируется и содержит баги** →
   пропуск удаления детей, re-append всего keyed-списка, replaceNode-in-reuse,
   cleanup по `ObjectIdentifier(JSObject)` не срабатывает, сломанная гидратация.
   **6 находок, один непокрытый слой.**
3. **Экранирование на строковых выходах — ничьё** → SSR.swift, StaticRenderer,
   PageRenderer, StyleSheetManager. **5 security-находок, один отсутствующий
   helper.**

## Что спроектировано ХОРОШО (сохранить)

- `TagBuilder` — полный и аккуратный (buildBlock/Either/Optional/Array/
  LimitedAvailability, parameter-pack `TupleTag` без боксинга).
- `Reconciler` — чистый, `Sendable`, патчи как данные; keyed-diff реально
  работает и покрыт тестами. Это *сильная* половина рантайма.
- `SwiftWUIStyles` — типобезопасные CSS-энумы + string-fallback, `Theme` на
  CSS-переменных, детерминированный FNV-1a хэш для responsive-классов.
- `Renderer`/`TestRenderer` — правильная host-agnostic архитектура для тестов.
- `Router` — чистые value-типы, Foundation-free.
- **Showcase** — сильнейший актив проекта: 12 глав, live-превью на реальном
  API (проверяются `swift build`), Playwright E2E/visual/a11y. Выше уровня
  всей Swift-web экосистемы. Это и есть будущий сайт документации.

## CRITICAL

### C1. `@State` не имеет идентичности по позиции в дереве — состояние каждого вложенного компонента уничтожается на каждом ре-рендере
`Sources/SwiftWUIState/State.swift:25` · подтверждено эмпирически (TestRenderer)

`StateStorage` создаётся в `State.init`, который выполняется заново каждый раз,
когда body родителя переисполняется. Идентичность существует только на корне
маршрута (`Application.swift:149-154` кэширует `AnyTag`). Любой вложенный
компонент пересоздаётся → его `@State` сбрасывается при *любом* изменении
состояния где угодно в дереве. Вложенный счётчик не может дойти до 1: клик
инкрементирует storage рендера №1, вызванный ре-рендер создаёт новый storage,
показывающий 0. Реальный сценарий: страница с `@State query` и дочерним
`SearchFilters` с `@State expanded` — каждое нажатие клавиши сбрасывает
`expanded` и весь локальный state детей.

**Это корневая причина ~10 других багов** (`.task`/`.onChange` идентичность,
переиспользование EventListenerID, утечка реестра, сброс NavigationStack,
морфинг ConditionalTag).

Фикс: `RenderContext` — стек структурного пути (тип + индекс сиблинга + `.id()`
ключ), протолкнутый через единственную точку рекурсии `resolveTagBody`
(`TagNodeConvertible.swift:124`), и таблица `[Path: StateStorage]`. `@State`
резолвит storage через lookup, а не аллоцирует в init. **Публичный API не
меняется.** Оценка: 6–8 чел./дней.

## HIGH — Безопасность (XSS/traversal)

### S1. SSR встраивает `initialState`/`themeCSS`/inline-CSS без экранирования → `</script>`-breakout XSS
`Sources/SwiftWUIRuntime/SSR.swift:115`
`initialState` (сериализованное состояние приложения, обычно с
пользовательскими строками) вставляется сырым в `<script type="application/json">`.
Значение с `</script><script>…` завершает блок и исполняет чужой скрипт. То же
с `</style>` в CSS. Фикс: экранировать `<`→`<` в JSON, отклонять `</style`.

### S2. StaticRenderer пишет значения `class`/`style` без HTML-экранирования → attribute-breakout
`Sources/SwiftWUIRuntime/StaticRenderer.swift:59`
Текст и атрибуты экранируются, а имена классов и объявления стилей — нет.
`.style("background", userValue)` с двойной кавычкой вырывается из `style="…"`
и вставляет произвольные атрибуты (`onmouseover`). То же в
`PageRenderer.swift:96` (S-medium ниже) и `StyleSheetManager.swift:76`
(CSS-breakout через `}`).

### S3. Path traversal в dev-сервере, слушающем на 0.0.0.0
`Sources/SwiftWUICLI/DevServer.swift:100`
Catch-all статик-роут конкатенирует сырой путь запроса с output-каталогом без
нормализации и проверки `..`. Сервер жёстко привязан к `0.0.0.0` (строка 66)
при печати localhost-URL, с `Access-Control-Allow-Origin: *`.
`curl --path-as-is 'http://<host>:8080/../../../../etc/passwd'` → 200 + файл.
Любой в той же сети читает произвольные файлы разработчика (напр. `~/.ssh`),
пока запущен `swiftwui dev`. Фикс: `realpath` + prefix-guard; дефолт
`127.0.0.1`, опциональный `--host`.

### S-med. `Link`/`A` не санируют схему URL → `javascript:` href исполняется по клику
`Sources/SwiftWUIRouter/Link.swift:38` — одноклик-XSS для любого приложения,
строящего href из недоверенного ввода. Фикс: разрешить только относительные,
`http(s):`, `mailto:`, `tel:`.

### S-med. Сгенерированный `index.html` грузит CDN-скрипты без SRI и без CSP
`Sources/SwiftWUICLI/Templates/showcase/index.html:20` — highlight.js с jsDelivr
без `integrity=`, нет CSP. Компрометация CDN → произвольный JS в каждом
`swiftwui init` проекте (+ `SyntaxHighlight.swift:35` пишет вывод в `innerHTML`).

## Архитектура / API (judgment-уровень, не баги)

- **Именование `Tag` вместо `View`** конфликтует с `Testing.Tag` — тесты
  вынуждены писать `SwiftWUICore.Tag`. Переименовать до 1.0 (`View`, с
  `typealias Tag` deprecated-шимом).
- **9 library-продуктов на 9.3k строк** — переизбыток; umbrella
  `@_exported`-реэкспортит всё, никто не импортирует гранулярно. Оставить 2
  продукта (umbrella + Core).
- **Vapor 4 в пакете фреймворка** — изолирован в CLI-таргете, но `Package.resolved`
  пинит 32 пакета; каждый contributor-билд компилит стек Vapor. Вынести CLI в
  отдельный пакет.
- **`ForEach(_:id:)`** молча игнорирует key-path и не компилируется для
  не-`Identifiable` (`ForEach.swift:62`). Реализовать или удалить.
- **`ConditionalTag` без branch-identity** — ветки if/else с одинаковым корневым
  тегом морфятся на месте, утечка stale-состояния (`ConditionalTag.swift:7`).
- **Модификаторы дропаются на `Text`** — `Text("x").style(...)` компилируется,
  стиль молча теряется (`TagNodeConvertible.swift:83`).
- **Три несовместимые системы модификаторов** — event-модификаторы работают
  только на конкретных HTML-тегах, не на кастомных компонентах / после `.style`.
- **Один обработчик на тип события** — `.onClick{a}.onClick{b}` теряет `a`;
  `EventHandler` без event-объекта (нет preventDefault/stopPropagation).
- **Нет `<label>` и ~15 частых тегов, нет generic `Element(tagName:)`** —
  добавление тега требует ручной 7-полевой структуры.
- **@AppStorage/@SessionStorage** экземпляры одного ключа не видят записи
  друг друга (`AppStorage.swift:60`).
- **Page title/meta** никогда не применяются на клиенте — `document.title`
  устаревает при SPA-навигации (`Page.swift:24`).
- **SSR-глобалы под многопоточным Vapor** — реестр/контексты — процесс-wide
  синглтоны; долгоживущий SSR-сервер течёт по записи на обработчик на запрос
  (`Renderer.swift:44`).

## Рекомендация: внутренний частичный редизайн

Консенсус панели (2 из 3 — partial-redesign, 1 — keep-and-fix, но и он требует
того же нового `RenderContext`). Единый механизм закрывает ~15 багов сразу.

### Дорожная карта (по фазам, каждая шиппится зелёной)

**Фаза 0 — безопасность + правда (1–2 недели, точечные фиксы, без архитектуры):**
один общий escaping-helper на 4 выхода (S1/S2 + PageRenderer + StyleSheetManager);
path-guard + `127.0.0.1` в dev-сервере (S3); санитизация схемы в `Link`/`A`;
SRI+CSP в шаблоне; `make ci`/`make dev` (H21, pipefail); pipe-drain в
WASMBuilder (H20); guard удаления в ProductionBuilder (H23); versioned-зависимость
в скаффолде (H22); `percentDecode` UTF-8 (H15); docs URL/`.hex`/`swiftwui-init`.

**Фаза 1 — идентичность (ядро редизайна, 4–8 недель):** `RenderContext` +
persistent instance-tree, протолкнутый через `resolveTagBody`; `@State`/`.task`/
`.onChange`/`@Environment`/обработчики принадлежат экземпляру; **реальный unmount**
(отмена task, disconnect observers, release handlers). Закрывает C1, H1, H3, H6,
H7, H8, H9, H16. Публичный API не меняется — 51 нативный тест + Showcase +
Playwright служат регрессионной обвязкой.

**Фаза 2 — рантайм-glue (2–3 недели):** перехват `Link` + сидирование из
`window.location` + pushState + guard-redirects + `document.title` (H12/H13/H14);
controlled-inputs через live DOM-свойства (H17/H19/Toggle); фиксы применения
патчей на `DOMOperations`-протоколе + нативный MockDOM (H2/H5/H11) — делает
непокрытый слой тестируемым.

**Фаза 3 — конкурентная позиция:** гидратация на instance-tree (или демоут SSR
до SSG, пока не готово, H4); generic `Element(tagName:)` + недостающие теги;
event-объект в обработчиках (deprecated-шимы для `() -> Void`); split CLI в
свой пакет; DocC + `.spi.yml`.

### Стратегия документации

Инвертировать доверие к тому, что компилит CI. **Showcase → официальный сайт**
(он уже выше уровня экосистемы и догфудит фреймворк). DocC — источник правды по
API (добавить `swift-docc-plugin`, чтобы docs.yml мог позеленеть; удалить

getting-started.md переписать под реальный `swiftwui` CLI со scaffold-roundtrip
проверкой. `make ci` починить, чтобы он вообще мог упасть.
