# SwiftWUI Showcase — Apple Tutorials Fidelity Pass

**Date**: 2026-05-14
**Status**: Approved (brainstorming)
**Author**: Brainstorming session (extends `2026-04-29-showcase-template-design.md`)
**Topic**: Bring the existing 13-route showcase template to pixel-faithful parity with Apple's "Develop in Swift Tutorials" reference (https://developer.apple.com/tutorials/develop-in-swift/hello-swiftui), upgrade ScrollyTeller, replace raw `.style()` calls with typed modifiers, add hybrid live/screenshot previews, and ship a Playwright suite covering smoke + interaction + accessibility + visual regression + per-preview snapshots.

This spec inherits all architecture, file layout, and CLI integration decisions from `2026-04-29-showcase-template-design.md`. Nothing in that doc is repealed.

---

## 1 · Goal

The showcase already ships 13 routes (`/`, `/learn/hello`, `/learn/state`, `/learn/modifiers`, `/learn/lists`, `/learn/forms`, `/learn/routing`, `/learn/async`, `/learn/theming`, `/learn/a11y`, `/learn/errors`, `/learn/ssr`, `/learn/pwa`) and a custom `ScrollyTeller` component. This pass elevates the work to match the **cited Apple reference exactly**, replacing the council-explored alternatives that were rejected.

Concrete outcomes:

1. Apple Develop-in-Swift-Tutorials visual fidelity: true-black canvas (dark) / true-white canvas (light), top-bar dual dropdown navigation (chapter picker + section picker with "N of M" pagination), mint-teal accent (dark) / Apple-blue accent (light), step cards with active-state vertical bar, sticky right-column code panel with line-number gutter and scroll-synced line highlighting.
2. ScrollyTeller v2: scroll-synced code-line highlight (`highlightLines: [Int]` per step), step nav buttons (`← Prev` / `Next →`), preview crossfade, active-step left bar, mobile fallback (sticky un-sticks below 760px).
3. Hybrid preview rendering — `PreviewKind` enum lets each step opt into `.live(AnyTag)` (current behaviour) or `.screenshot("path.png")` (pre-rendered PNG generated by a build-time Playwright job).
4. `.style()` migration: 693 raw `.style("css-prop", value)` calls in `Examples/Showcase/Sources` collapse to typed modifiers. ~10 new typed modifiers added to `SwiftWUIStyles` for high-frequency missing props. Only `.style("--swui-foo", token)` custom-prop assignments survive.
5. Browser-window preview chrome — traffic-light dot row + faux `localhost:8080` address bar around every preview pane.
6. Playwright suite at `Examples/Showcase/tests/` covering: smoke (13 routes load, no console errors), nav (dropdown opens, URL syncs, SPA back/forward, theme toggle persistence), scrolly (step advance, line-highlight, sticky panel), a11y (axe-core, WCAG 2.1 AA), visual regression (13 routes × {desktop, mobile} × {light, dark} = 52 baselines), per-preview snapshot diff.

## 2 · Non-goals

- Live in-browser code editing (Monaco / CodeMirror / WASM REPL). Apple Tutorials does not edit; we do not edit.
- Per-step parameter knobs (sliders, color pickers, dropdowns) that mutate pre-baked Tag variants.
- iPhone bezel preview chrome. SwiftWUI is a web framework — use a browser window frame, not a device frame.
- Search bar in top bar (the cited Apple Tutorials page does not surface search, only the two breadcrumb dropdowns).
- Left sidebar navigation. The cited reference uses dual top-bar dropdowns only.
- TOC "On this page" rail. Not present in the cited reference.
- New chapters or IA changes to the 12-chapter linear pedagogy.
- Removing `.style()` from `Sources/SwiftWUIHTML/Modifiers/OverlayModifiers.swift` and `Sources/SwiftWUIStyles/AnchorPositioning.swift`. Those raw calls live inside typed-modifier internals and are not user-facing.

- `Examples/Showcase/Sources/Showcase/Pages/Chapters/*.swift` (12 files): convert every step's `preview:` field to the new `PreviewKind`; add `highlightLines: [Int]` per step; remove all `.style(_:_:)` calls in favor of typed modifiers; refit each chapter's prose into the new step-card style.
- `Examples/Showcase/Sources/Showcase/Pages/HomePage.swift`: same `.style()` cleanup; theme toggle works on home page too.
- `Examples/Showcase/tests/` (new, npm-based): Playwright config + 6 spec files + `__screenshots__/` baseline directory. New `package.json` for test deps only.
- `Examples/Showcase/Resources/snapshots/` (new): pre-rendered preview PNGs generated by `make showcase-snapshots`. Files committed to git.

- `Sources/SwiftWUICLI/Templates/showcase/`: regenerated by `make sync-templates` after the above changes land. No manual edits.
- `.github/workflows/ci.yml`: add Playwright job that runs after showcase tests pass.

### 4.3 Top bar — dual dropdown

Replaces the existing `SiteChrome` header.

```
┌────────────────────────────────────────────────────────────────────────────┐
│ Develop in Swift Tutorials ┃ [Chapter ▾] [Section ▾  1 of N]      [☼ / ☾] │
└────────────────────────────────────────────────────────────────────────────┘
                          ↑ word "Tutorials" rendered in --swui-accent
```

`[Chapter ▾]` popover:

```
Essentials                Building UI               Production
  1 Hello, SwiftWUI         4 Lists                   8 Theming
  2 State                   5 Forms                   9 Accessibility
  3 Modifiers               6 Routing                10 Error handling
                            7 Async                  11 SSR
                                                     12 PWA
```

Active item highlighted with `background: var(--swui-surface-2)` + `border: 1px solid var(--swui-accent-strong)`.

`[Section ▾]` popover lists the steps of the currently-routed chapter:

```
Introduction
1 Conform a struct to Tag
2 Compose with @TagBuilder
3 Mount on a DOM element
4 Style with chained modifiers
```

`N of M` chip on the right shows current step / total steps for the chapter. Updates as the user scrolls (driven by the same IntersectionObserver that tracks ScrollyTeller's `currentStep`).

Implementation: leverages existing `AnchorPositioning.swift` for popover placement. Two new SwiftWUI components:

```swift
TutorialTopBar(currentChapter: ChapterID, currentStep: Int, stepTotal: Int) -> some Tag
ChapterPickerPopover(active: ChapterID) -> some Tag
SectionPickerPopover(chapter: ChapterID, active: Int) -> some Tag
ThemeToggle() -> some Tag        // sun / moon icon, syncs <html data-theme>
```

Keyboard: `Esc` closes any open popover. `↑ / ↓` moves selection in the active popover. `Enter` navigates.

### 4.4 ScrollyTeller v2

Existing `ScrollyTeller.swift` extends `Step` from:

```swift
struct Step: Identifiable {
    let number: Int
    let title: String
    let prose: String
    let code: String
    let preview: AnyTag
    var id: Int { number }
}
```

to:

```swift
struct Step: Identifiable {
    let number: Int
    let title: String
    let prose: String
    let code: String
    let highlightLines: [Int]      // 1-indexed, applies --swui-code-line-hl
    let preview: PreviewKind        // .live(AnyTag) or .screenshot(String)
    var id: Int { number }
}
```

`PreviewKind`:

```swift
public enum PreviewKind {
    case live(AnyTag)
    case screenshot(String)        // path relative to Resources/snapshots/
}
```

Layout (desktop ≥ 760px):

```
┌─ STEP COLUMN (left, 55%) ──────────┐  ┌─ CODE+PREVIEW (right, 45%, sticky) ┐
│ ┃ Step 1                            │  │ ┌──────────────────────────────┐ │
│ ┃ Title of step                     │  │ │ ◉ ◉ ◉  localhost:8080         │ │
│ ┃ Prose paragraph with inline code  │  │ ├──────────────────────────────┤ │
│ ┃ chips and Note callouts.          │  │ │                              │ │
│ ⠀                                    │  │ │   < preview pane >            │ │
│ ⠀ Step 2 …                           │  │ │                              │ │
└────────────────────────────────────┘  │ ├──────────────────────────────┤ │
                                        │ │ ← Prev step    Step 1 / 4    │ │
                                        │ │                  Next step → │ │
                                        │ ├──────────────────────────────┤ │
                                        │ │ 1  struct Greeting: Tag {     │ │
                                        │ │ 2    var body: some Tag {     │ │
                                        │ │ 3      H1 { Text("…") }        │ │  ← lines 3-4
                                        │ │ 4    }                         │ │     highlighted
                                        │ │ 5  }                          │ │
                                        │ └──────────────────────────────┘ │
                                        └──────────────────────────────────┘

Active step = mint-teal vertical bar (▌) on the left edge of the step card.
Inactive step = transparent vertical bar (preserves layout).
```

Mobile (< 760px): sticky panel un-sticks. Order: step prose → code/preview pair → next step prose.

IntersectionObserver retains its current job (advance `currentStep`). New: `currentStep` is now also bound to the `Section ▾` dropdown's "N of M" chip.

### 4.5 Preview frame (browser window chrome)

New component:

```swift
struct PreviewFrame<Content: Tag>: Tag {
    let label: String      // e.g. "localhost:8080"
    @TagBuilder let content: () -> Content

    var body: some Tag {
        Div {
            // window chrome
            Div {
                Div { EmptyTag() }.background(.color("#ff5f57")).width(.px(12)).height(.px(12)).borderRadius(.pill)
                Div { EmptyTag() }.background(.color("#ffbd2e")).width(.px(12)).height(.px(12)).borderRadius(.pill)
                Div { EmptyTag() }.background(.color("#28c840")).width(.px(12)).height(.px(12)).borderRadius(.pill)
                Spacer()
                Text(label)
                    .fontFamily("var(--font-mono)")
                    .fontSize(.px(11))
                    .foregroundColor(.token("swui-fg-3"))
                Spacer()
            }
            // body slot
            Div {
                content()
            }.padding(.px(20))
        }
        .border(width: .px(1), style: .solid, color: .token("swui-border"))
        .borderRadius(.px(10))
        .background(.token("swui-bg"))
        .overflow(.hidden)
    }
}
```

When `PreviewKind == .screenshot(path)`, content is an `<img src="\(path)" alt="preview" />` Tag, rendered inside the same chrome.

### 4.6 Snapshot generation

`make showcase-snapshots`:

```
1. swift run swiftwui-dev dev --target Showcase --port 4173  (background)
2. cd Examples/Showcase/tests && npx playwright test --grep '@snapshot'
3. Playwright iterates routes, locates preview panes by data-attr,
   takes element screenshot, writes to ../Resources/snapshots/<chapter>-<step>.png
4. Kill dev server
```

The snapshot job is **author-invoked** when the author wants to convert a `.live` to a `.screenshot`. Not run on every build.

PNGs are committed to git under `Examples/Showcase/Resources/snapshots/`. `Bundle.module` makes them addressable at runtime via `Resources/snapshots/<name>.png`.

### 4.7 `.style()` migration

```swift

.textTransform(.uppercase | .lowercase | .capitalize | .none)
.letterSpacing(CSSLength)       // .em, .px, .rem, .normal
.lineHeight(CSSLineHeight)      // .em, .px, .unitless(Double), .normal
.whiteSpace(.normal | .nowrap | .pre | .preLine | .preWrap)
.textAlign(.left | .right | .center | .justify | .start | .end)
.textDecoration(TextDecoration)
.textIndent(CSSLength)
```

**Add to** `Sources/SwiftWUIStyles/StyleModifier.swift` (extend existing groups):

```swift
.backdropFilter(String)
.cursor(.pointer | .default | .text | .grab | .grabbing | .notAllowed | .crosshair)
```

**Migration script (one-time):** `Scripts/migrate-style-calls.swift` (not committed, ephemeral) does a token-by-token rewrite per file. After it runs, a manual review pass catches edge cases. The PR removes the script.

**Acceptance:**


### 4.8 Playwright suite layout

```
Examples/Showcase/tests/
├── package.json
├── playwright.config.ts            # base URL http://localhost:4173, projects: chromium, mobile-safari
├── tsconfig.json
├── lib/
│   ├── routes.ts                   # const ROUTES = ['/', '/learn/hello', …]
│   ├── viewports.ts                # desktop (1280×800), mobile (393×852)
│   ├── themes.ts                   # ['light', 'dark']
│   └── helpers.ts                  # setTheme(), waitForHydration()
├── smoke.spec.ts
├── nav.spec.ts
├── scrolly.spec.ts
├── a11y.spec.ts
├── visual.spec.ts
├── preview.spec.ts
└── __screenshots__/                # baseline PNGs, committed
```

Vite dev server boots at port **4173** (Playwright's default) before tests; teardown stops it. This is a test-only port — `make dev` keeps its existing `8080` so concurrent local development is unaffected.

Per-spec scope:

- `smoke.spec.ts` — every route returns 200, document.title set, console.error count == 0, h1 visible above the fold.
- `nav.spec.ts` — click `[Chapter ▾]` → popover opens; click chapter "State" → URL is `/learn/state`; back button → previous chapter; theme toggle → `<html data-theme>` flips and persists across reload.
- `scrolly.spec.ts` — scroll to step 2 → `[data-step-active="2"]` present; `[data-line-hl]` set on the lines listed in `Step.highlightLines`; sticky panel `top` value > 0 throughout the scroll.
- `a11y.spec.ts` — `axeBuilder.analyze()` per route in both themes; fail on any violation tagged WCAG 2.1 AA.
- `visual.spec.ts` — full-page screenshot per route × {desktop, mobile} × {light, dark} = 52 baselines. Diff threshold 0.1%, with anti-aliasing tolerance.
- `preview.spec.ts` — for each step in each chapter, screenshot `[data-preview-pane]`, diff against baseline. This catches preview rendering drift independently of full-page visual.

Snapshot baselines are first generated locally by the author with `npx playwright test --update-snapshots`, then committed. CI fails on drift.

## 6 · Risks and mitigations

| Risk | Mitigation |
|---|---|
| Visual baseline thrash (every CSS tweak invalidates 52 baselines) | Diff threshold 0.1% with anti-alias tolerance; author updates baselines via `--update-snapshots` and reviewer compares before/after PNGs in PR diff |
| `prefers-color-scheme` detection inside snapshot tests | Playwright `colorScheme: 'light' | 'dark'` per project; tests force both modes explicitly, not via system preference |
| Sticky panel breaks on Safari < 16 with nested overflow | Drop sticky behavior on `:not(@supports (position: sticky))` and fall back to in-flow layout; documented in chapter README |
| Snapshot PNGs balloon git history | Use git LFS only if total size > 5 MB; we expect ~52 routes × 30 KB + 60 previews × 8 KB ≈ 2 MB total — keep in-tree |
| `.style()` migration introduces visual regression | P2 acceptance: Playwright `visual.spec.ts` baselines captured **before** P2, re-run **after** P2; diff must be zero |
| ScrollyTeller `Step` shape change (added `highlightLines`, `preview` type changed from `AnyTag` to `PreviewKind`) breaks 12 chapter call sites | Phase P4/P5 author touches every chapter file in the same commit; native tests catch shape mismatch at compile time |
| Light-mode aesthetic drifts from Apple reference (Apple shows mostly dark) | Light tokens derived from Apple's `developer.apple.com` light-section palette (not Tutorials); ui-designer reviews light mode separately in P0 |
